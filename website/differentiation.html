Differentiation

Differentiation is a technique you apply to a maths function — instead of giving you the y for a given x (f(x)), it gives you the gradient at that x.
A lot of optimisation, statistics and computer maths involves this, so it's definitely worth knowing.
I'll briefly go over what a derivative is, some examples of how to find it using a computer, and finally what I think is the fastest and most accurate way to calculate a derivative on a computer.
Further reading: thenumb.at/Autodiff

What is differentiation?

Differentiation finds the gradient of a graph. You have likely come across a gradient in school as the difference in two y co-ordinates divided by the difference in two x co-ordinates, where each x and y is taken from two points on a straight line: $$y_2 - y_1 \over x_2 - x_1$$ This works perfectly, but only for a straight line. What if we wanted the gradient at an exact point on a continuously changing function? We can still use this equation, but it will be very hard to get the exact value of the derivative at an exact point.
The solution is to rewrite the simple definition above more generally, using functions and limits. So \(y_1\) and \(y_2\) become \(f(x)\) and \(f(x + h)\), and \(x_1\) and \(x_2\) become \(x\) and \(x + h\). We then take the limit as \(h\) tends to 0, so one point tends towards the other and we get the gradient at an exact point. This is Newton's difference quotient:

Newton's difference quotient

$$ f'(x) = \lim_{h \to 0} \frac{f(x + h) - f(x)}{h} $$
One question you might have is why there are no x co-ordinates in the bottom of the fraction. That's because it has been simplified from this: $$ \frac{f(x + h) - f(x)}{(x + h) - x} $$ where the x's cancel out.
From this we can now move on to our first basic form of differentiation.

Finite Difference Method

There are a number of ways to work out the derivative from Newton's difference quotient. The finite difference method is probably the most straightforward and well known — it evaluates the difference quotient with a small, fixed h instead of taking the limit. Here is some example code for illustration:

class Differentiator:
    def __init__(self, func):
        self.func = func

    def finite_difference(self, x, h=0.001):
        numerator = self.func(x + h) - self.func(x)
        return numerator / h


def square(x):
    return x**2

def cube(x):
    return x**3

sq_diff = Differentiator(square)
print(f"Derivative of x^2 at 2: {sq_diff.finite_difference(2)}")

cube_diff = Differentiator(cube)
print(f"Derivative of x^3 at 2: {cube_diff.finite_difference(2)}")
          

python3 finite_difference.py
Derivative of x^2 at 2: 4.000999999999699
Derivative of x^3 at 2: 12.006000999997823
This is a VERY fast way of calculating a derivative, as it only needs two evaluations of the function. But there is one downside — it is not very accurate. This can be seen above, where the derivative of \(x^2\) at 2 is calculated as 4.00099999... when in reality it is 2(2) = 4.

Most of this error isn't floating point rounding. It's truncation error, from using a fixed h instead of taking the limit: $$ \frac{(2 + h)^2 - 2^2}{h} = \frac{4h + h^2}{h} = 4 + h $$ so with h = 0.001 the method gives exactly 4.001. Floating point rounding only causes the tiny difference at the end (4.000999999999699 instead of 4.001). Making h smaller shrinks the truncation error, but make it too small and the rounding error takes over, so this method can never be exact.

So how can we increase the accuracy? One option would be to hard code every differentiation rule, but with all the different rules it quickly becomes obvious that this would take a huge amount of time. On top of that, complex problems can involve applying many rules many times over, which can slow things down. But don't worry, there is a solution — automatic differentiation.

Automatic Differentiation

Automatic differentiation (AD) works out the derivative alongside the function itself. It has none of the truncation error of finite differences, so it is exact up to floating point precision, while still being fast.

The first time automatic differentiation was written about and used was in the 1960s but nothing much came of it at the time, and only recently has automatic differentiation taken off and gained mass popularity. The reason for this sudden popularity is AI, where finding the derivative for back propagation became very important.

There are a few methods for AD, all with their pros and cons. The first that we can look at is forward mode AD.

Forward Mode

Forward mode differentiation works using a concept called dual numbers.

Dual Number

Dual Numbers are a core concept for forward mode AD, so knowing them is essential. It is pretty simple and it is defined by these two rules: \begin{align*} \epsilon^2 &= 0 \tag{1} \label{epsilon rule 1}\\ \epsilon &\neq 0 \tag{2}\label{epsilon rule 2}\\ \end{align*} Looking through these rules you quite quickly realise this is a strange variable, as the only real number that equals 0 when squared is 0 itself, however \eqref{epsilon rule 2} says that it can't be this.
You can think of it as similar to the imaginary number i, where \(i^2 = -1\) seems to make no sense, as no real number multiplied by itself gives -1.
The most important thing about dual numbers is the following proposition $$ f(x + \epsilon) = f(x) + \epsilon f'(x) $$ where we can see that just by adding \(\epsilon\) to our variables we can get the derivative of any function!

Here is a quick example of the proposition: \begin{align} f(x) &= x^2 + 6x - 1 \\ f'(x) &= 2x + 6 \tag{*} \label{deriv} \end{align} \begin{align*} f(x + \epsilon) &= (x + \epsilon)^2 + 6(x + \epsilon) - 1 \\ &= x^2 + 2x\epsilon + \cancel{\epsilon^2} + 6x + 6\epsilon - 1 \\ &= (x^2 + 6x - 1) + 2x\epsilon + 6\epsilon \quad \text{group like terms}\\ &= f(x) + \epsilon \underbrace{(2x + 6)}_{\text{matches } \eqref{deriv}} \\ f(x + \epsilon) &= f(x) + \epsilon f'(x) \end{align*}
Some quick rules before we create our code. For two dual numbers \(a + b\epsilon\) and \(c + d\epsilon\):
Addition $$\begin{align*} &(a + b\epsilon) + (c + d\epsilon) \\ &= (a + c) + (b + d)\epsilon \end{align*}$$ Multiplication $$\begin{align*} &(a + b\epsilon) \times (c + d\epsilon) \\ &= ac + (ad + bc)\epsilon + \cancel{bd\epsilon^2} \\ &= ac + (ad + bc)\epsilon \end{align*}$$ These are exactly what the __add__ and __mul__ methods below do. Cool! With those rules in mind, we can now write our code.
Thanks to Computerphile for this code. 

class ForwardAutoDiff:
    def __init__(self, real, dual):
        self.real = real
        self.dual = dual

    def __add__(self, other):
        real = self.real + other.real
        dual = self.dual + other.dual
        return ForwardAutoDiff(real, dual)

    def __mul__(self, other):
        real = self.real * other.real
        dual = self.real * other.dual + self.dual * other.real
        return ForwardAutoDiff(real, dual)

 
def diff(f, x):
    return f(ForwardAutoDiff(x, 1)).dual


def f(x):
    return x * x + ForwardAutoDiff(6, 0) * x + ForwardAutoDiff(-1, 0)


if __name__ == "__main__":
    x = 3
    print(diff(f, x))  # expected: 2x + 6 = 12

          

python3 forward_differentiation.py
12
Code starts at line 25 where it sets x to 3 and calls diff, passing in f, the function created in line 21 as well as x, which we set to 3. diff then passes the ForwardAutoDiff class into the f function with parameters 3 (for the x) and 1 for our dual. Looking at line 22 we will get the equation: $$\begin{align*} &\text{ForwardAutoDiff}(3,1) \times \text{ForwardAutoDiff}(3,1) \\ +\, &\text{ForwardAutoDiff}(6,0) \times \text{ForwardAutoDiff}(3,1) \\ +\, &\text{ForwardAutoDiff}(-1,0) \end{align*}$$ Which thanks to operator overloading becomes: $$\begin{align*} &\text{ForwardAutoDiff}(9,6)\\ +\, &\text{ForwardAutoDiff}(18,6)\\ +\, &\text{ForwardAutoDiff}(-1,0) \end{align*}$$ due to the __mul__ method and finally: $$\begin{align*} &\text{ForwardAutoDiff}(26,12)\\ \end{align*}$$ due to the __add__ method. So our final answer is ForwardAutoDiff(26,12), where 26 is \(f(3)\) and 12, the dual part, is the EXACT derivative \(f'(3) = 2(3) + 6\)!!! All through simple maths instructions alone.

Summary

  • Finite differences estimate the derivative using a small, fixed h. They are simple and fast, but always carry truncation error, and rounding error takes over if h is made too small.
  • Forward mode automatic differentiation carries a dual part alongside every value, using \(\epsilon^2 = 0\), so the derivative comes out exactly (up to floating point precision) with no h to choose.
  • For \(f(x) = x^2 + 6x - 1\) at \(x = 3\), finite differences only approximate the derivative, while forward mode gives \(f(3) = 26\) and \(f'(3) = 12\) in a single pass.
